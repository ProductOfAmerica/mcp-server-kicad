# CLAUDE.md

CodeRabbit reads this file as review criteria (its `code_guidelines` default, left on in `.coderabbit.yaml`), so a rule written here is enforced on pull requests, and a stale one misdirects them.

## Commands

```bash
uv sync --frozen --all-extras --dev   # setup (CI uses exactly this)
uv run pytest tests/test_cst.py -v    # one file (no -n: worker startup dwarfs the run)
uv run pytest -k test_name            # one test
uv run pytest -v -n auto              # full suite (CI uses -n auto everywhere); once, before the PR
HYPOTHESIS_PROFILE=nightly uv run pytest -n auto -rs tests/test_ladder_*.py  # the nightly set
uv run ruff check .                   # lint
uv run ruff format --check .          # format check (CI enforces)
uv run pyright                        # type check (basic mode)
uv run python mcp_server_kicad/_cst.py  # CST self-check (demo() asserts)
npx @modelcontextprotocol/inspector --cli uv run mcp-server-kicad --method tools/list  # this checkout's tools, as a client sees them
```

Tests that shell out to `kicad-cli` (ERC, DRC, exports) auto-skip when it is not installed; so do the `kicad-cli` checks of the autouse fixture in `tests/conftest.py`, which validates every KiCad file a test leaves in `tmp_path`, whatever its first bytes, empty files included: each `.kicad_sch` together with every sheet file below it, each loaded on its own; each `.kicad_pcb`; each `.kicad_sym` and `.kicad_mod`, loaded by `sym upgrade` or `fp upgrade --force --output` on a scratch copy, kicad-cli having no load-only command for a library. Its check of `sym-lib-table` and `fp-lib-table` needs no KiCad and runs everywhere: KiCad 9 decodes escapes in a table value and KiCad 10 decodes none, so a value holding a backslash or a double quote is refused, as is a table KiCad 9's lexer or the CST refuses, and one that does not open with `(` and its keyword at its first byte or holds more than whitespace after its closing paren, where KiCad 10's grammar starts and stops. Confirm `kicad-cli` resolves locally (`KICAD_CLI_PATH`, PATH, the macOS app bundle, or the versioned Windows install roots) or a green run proves less than it looks. Even then, a KiCad 9 `kicad-cli` skips KiCad 10 boards and libraries (`_cli_can_load_board`, `_cli_can_load_library`), so those are validated only where kicad-cli is 10 or newer: the `kicad-suite.yml` 10.0 leg, macOS and Windows. A test that leaves a placeholder or a deliberately malformed input in `tmp_path` names each such file, by its path under `tmp_path`, in `@pytest.mark.kicad_placeholder(...)`: the oracle skips exactly those files, and fails a passing test that left no file at a path its marker names. `@pytest.mark.no_kicad_validation` turns the whole oracle off, for a test whose subject is the malformed file.

That validation fixture is what makes the suite slow: it spawns a `kicad-cli` process per generated schematic, board and library, ~200 to 400 ms each. It is memoised on a UUID-normalised digest, of the file and, for a schematic, every sheet below it, since loading a schematic loads its sheets; so each distinct body is validated once per process rather than once per test (376 spawns -> 186 for schematics, measured 2026-08-10); `test_validation_memo.py` guards the key against collapsing anything but a UUID. With `-n auto` on top, a full local run went 213 s -> 40 s on 16 cores.

Run a server by hand: `uv run mcp-server-kicad` (stdio), or under the MCP Inspector with `npx @modelcontextprotocol/inspector uv run mcp-server-kicad`. README.md's Inspector command and `.mcp.json` both launch `uvx --from mcp-server-kicad`, which is a PyPI release, not this checkout, so the `kicad` MCP tools in a Claude Code session here do not see local changes.

## Architecture

Five `MCPServer` servers, one module each: `schematic.py`, `pcb.py`, `project.py`, `symbol.py`, `footprint.py`. Each defines its own `mcp` instance and `main()` console script; `server.py` merges all tools into the unified `kicad` server through `_copy_tools`, which reaches into the private `_tool_manager._tools` (no public copy API; `test_tool_annotations.py` depends on the same internals). Every tool passes one of the annotation presets from `_shared.py` (`_READ_ONLY`, `_ADDITIVE`, `_DESTRUCTIVE`, `_EXPORT`) and returns a Pydantic model from `models.py` when it has structured output. The one exception to the presets is `autoroute_pcb`, whose own `_AUTOROUTE` sets `open_world_hint` because it downloads Freerouting. `test_tool_annotations.py` classifies every tool by name, so a new tool needs a row there.

### One parse/write stack: the CST substrate (`_cst.py`)

Stdlib-only, byte-preserving concrete syntax tree for s-expressions. Bytes in, bytes out; `serialize(parse(b)) == b` by construction; malformed input (an unbalanced paren, a string that does not close on its own line) raises instead of being repaired. As of slice 18 every tool's own reads and writes run on it: all `.kicad_sch` reads and writes, all board reads and writes including the `autoroute_pcb` internals, and the symbol/footprint library tools. Two writes are still performed by a subprocess and are outside it (`sym upgrade` and `fp upgrade`, permanently); see the invariant note below. One more design file comes out of a subprocess, as new output rather than an edit: `autoroute_pcb`'s `<stem>_routed.kicad_pcb`, which pcbnew's `SaveBoard` writes in pcbnew's own format while the input board stays untouched. Slice 18 deleted the version guard, so the substrate refuses no file on its format version and every tool's own reads and writes work on both KiCad 9 and KiCad 10 files. What a tool hands to an installed KiCad is another matter: `kicad-cli` (ERC, DRC, exports, jobsets, the library upgrades, `update_pcb_from_schematic`'s netlist export) and pcbnew (`fill_zones`, `autoroute_pcb`) can only work on files that install can load, and neither a KiCad 9 `kicad-cli` nor a KiCad 9 pcbnew can load a KiCad 10 board (both measured; see `_cli_can_load_board` in `tests/conftest.py` and `_require_pcbnew_era` in `pcb.py`). kiutils is a **test-only** dependency (the `dev` extra): it builds fixtures and reads written files back as an independent oracle, and nothing under `mcp_server_kicad` imports it (`test_runtime_imports_no_kiutils` scans for that).

Two helper modules back the subprocess tools. `_freerouting.py` serves `autoroute_pcb` (needs Java; resolves freerouting.jar via `FREEROUTING_JAR` or a cached auto-download) and hosts the shared pcbnew plumbing: `find_pcbnew_python` (`KICAD_PYTHON` first), `pcbnew_major`, and `wx_app_prelude`. `pcb.py` uses `pcbnew_major` to era-preflight `fill_zones` and `autoroute_pcb`: a KiCad 10 board on a pcbnew 9 refuses up front, and a KiCad 9 board routed through pcbnew 10 gets a result warning that the routed copy is KiCad 10 format. `_netlist_import.py` no longer runs under pcbnew: `update_pcb_from_schematic` does the import in-process (`pcb._apply_netlist_cst`) from a `kicad-cli` netlist. The module survives for two reasons: `pcb.py` imports its stdlib-only netlist helpers, and the three pcbnew scripts (`fill_zones`, autoroute's DSN export and SES import) import it BY NAME under pcbnew's interpreter, through `wx_app_prelude`, to reach `_ensure_wx_app`. Renaming it, or importing anything outside the standard library into it (this package included), breaks all three.

The governing invariant (non-negotiable): bytes the user did not ask to change reach the disk unchanged, and an edit that cannot be done correctly is refused with the file intact. It holds for every write this package performs, including the two a subprocess half-performs. `upgrade_symbol_lib` and `upgrade_footprint_lib` stay outside BYTE PRESERVATION permanently, because rewriting the file is the operation the user asked for and closing that would mean reimplementing KiCad's own format migration, but they are no longer outside ATOMICITY: `_upgrade_out_of_place` gives kicad-cli a scratch copy to truncate and lands the result through `_atomic_write`. Each still takes one bounded `.bak`, which is the undo for an upgrade that SUCCEEDED and is a different concern from a write that failed. Per-file, not per-library: an interrupted `.pretty` upgrade leaves some footprints migrated and none damaged. `fill_zones` and `update_pcb_from_schematic` used to be here and are not any more: a subprocess may compute (pcbnew's zone filler, `kicad-cli`'s netlist export) but never writes the user's board, and the tool writes it through the substrate. `docs/adr-cst-substrate.md` is the decision record; read it before touching any write path. Its status log records how each surface reached the substrate, slice by slice, and ends with the migration complete; append to it when a write path changes shape. The bar every slice cleared, and any new write path still has to clear, is a byte-preservation test, the ERC oracle, and the KiCad 10 CI gate.

Rules the ADR encodes that will bite if ignored:

- **CST I/O is bytes-only.** Never read a KiCad file in text mode on a write path; that rewrites CRLFs. Tokens are DSNLEXER's (a line whose first non-blank byte is `#` is whitespace, so is NUL, a double quote inside a bare run is one of its bytes, a string closes on its own line). Atom text decodes on demand, every escape KiCad's lexer does; `set_text` re-encodes as KiCad's Quotew does (the only lossy surface), quotes a bare value holding a bar or starting with `#`, and refuses a NUL, which no escape carries to KiCad 9. Free text therefore goes in through `set_text`, never through an f-string or an escape written by hand.
- **A number a writer puts in a file is the number KiCad holds, in KiCad's text.** KiCad keeps a coordinate or a distance as a whole count of internal units (`SCH_IU_PER_MM` in a schematic or symbol library, `PCB_IU_PER_MM` on a board or footprint) and prints it with FormatInternalUnits. A writer passes its file's scale, `_num(v, iu)` or `_fill_at(..., iu=...)`, and never `round(v, 4)`; a bare `_num(v)` is exact and only copies a number. An angle goes through `_angle_text`. A request is snapped (`_snap`) before any check that reads it, and the result reports the value written. `tests/test_ladder_r2_writers.py` sweeps the writers, so a new writer gets a case there. `set_page_size` is the exception: KiCad holds a User page in whole mils.
- **Board net references are version-gated with zero dialect overlap, and name a net the board holds**: emit numeric `(net N)` at or below `_NUMERIC_NET_VERSION_MAX` (20241229, defined in `pcb.py`), quoted `(net "NAME")` above it, and never copy a numeric net reference across versions. KiCad 10 silently rebinds numbers to the wrong net; its boards have no net table, so nets are derived from usage. A number written for a net is 0 or a row of the board's own table, checked before the write in `_set_item_net`: KiCad 9 binds a number only through a row, so any other number reads as no net, and `kicad-cli` loads such a board without complaint, so only the net judge in `test_output_validity.py`, the lexer port and pcbnew can see it. A quoted net atom is a name even when it is all digits (`_net_code` decides on the atom's raw bytes, never on decoded text). The tools read a bare number through the table's rows (`_bound_names`), else as no net on a KiCad 9 format board and as the net KiCad 10 made that many-th on a newer one, where a zone's number counts only if the zone is on copper when it is read and after its last child, and is no rule area (`_zone_keeps_number`). `_set_item_net` is the one place that spells no net, as KiCad's writer does per item kind and format: `(net 0)` or `(net "")` on a track, `(net 0)` with `(net_name "")` on a KiCad 9 zone, no token on a KiCad 10 zone or a copper shape.
- **Board CST cache** (`_open_pcb_cst`): parsed trees cached per resolved path keyed on mtime+size. Writers must pop their cache entry *before* mutating and never reinsert, so an exception mid-edit cannot leave a poisoned tree cached.
- **Every write goes through `_shared._atomic_write`.** A plain `write_bytes` opens with O_TRUNC, so anything that fails part way through leaves the file truncated, which is exactly what the invariant forbids. Measured on NTFS with a concurrent reader before this landed: 345 torn reads out of 800, including reads of zero bytes, against 0 out of 25,529 through the helper. A blocked replace retries briefly and then raises with the file intact; it never falls back to a direct write. `test_every_write_goes_through_atomic_write` scans the source, because a new direct write passes every functional test in the suite. It only sees `.write_bytes`/`.write_text`, so a write performed by an external process is invisible to it, which is exactly why the subprocess writers went unnoticed for so long; the two that remain are named above.
- **The invariant has two halves, enforced in different places.** `_atomic_write` is durability: the bytes arrive whole or not at all. Validity is separate and is enforced at the point of construction, because `(layer banana)` is a perfectly well-formed s-expression and only wrong in KiCad's semantics, so the CST cannot catch it. A value that reaches a *token* position must be checked before the write: against a closed set (`_check_rotation` in `_shared.py`, `_VALID_LABEL_SHAPES`, the `Literal` on `mirror`) or against the document's own table (`_resolve_layer_cst`, whose model is `_resolve_net_cst`). Free text is not in this class; `set_text` escapes it, and refuses a NUL. Patching these one parameter at a time has failed twice, so the regression net is `test_output_validity.py`, which sweeps hostile values off the live signatures, and the autouse `kicad-cli` oracle in `conftest.py`, which covers boards, symbol libraries, footprints and library tables as well as schematics.
- **Every read goes through `_shared._read_kicad_bytes` (or `_require_kicad_path` when the file goes to `kicad-cli` or pcbnew unread), and every output directory through `_ensure_dir`.** A tool's error message is the whole interface when something goes wrong, and a raw `FileNotFoundError` names neither the tool nor the parameter. Two messages, not one: a missing file says "not found: {path}", while an empty path says "none is configured" and points at the host config, because an unset default is not a typo. `_ensure_dir` keeps `mkdir(parents=True)`, so naming a fresh export folder still creates it; only an unreachable *root* (a typo'd drive, a disconnected share) is refused. `test_bad_path_contract.py` exercises every tool off the live registry, because a new tool that opens its file directly passes every other test in the suite.
- **`no_kicad_validation` suppresses that oracle, so reach for it only when the malformed file *is* the subject**, as in `test_cst.py`; a placeholder, or a malformed input that is not the subject, goes in `kicad_placeholder`, which skips that one file. Using `no_kicad_validation` to quiet a tool that writes a bad file is how a 45-degree rotation shipped: the test asserted the illegal angle had been written and switched the oracle off so nothing could object.
- **A footprint is moved, turned or flipped only through the orientation helper in `pcb.py`** (`_fp_translate`, `_fp_turn`, `_fp_rotate_to`, `_fp_flip`: KiCad's SetPosition, SetOrientation, Rotate and Flip), after its refusal gate `_fp_unsupported`, run before the cache pop. KiCad stores pad and text angles absolute, other positions footprint-relative, and a footprint's zones and KiCad 10 points in board coordinates, so a write that touches the footprint's `(at)` alone leaves the rest wrong.
- **`move_component` carries a placed symbol's fields with it, through `_connectivity.symbol_frames` and `carry`.** A property's `(at)` is the field's drawn sheet position, read in the frame in force where the property sits in the file, so the tool rewrites the symbol's last `(at)`, the one KiCad keeps, and carries every property's `(at)` by P' = S' + T' * T^-1 * (P - S), rewriting only atoms whose value changes. An angle `_connectivity._angle` cannot read as 0, 90, 180 or 270 (45, none, `inf`, `1e400`, `nan`; kicad-cli cannot load the sheet) is refused without a rotation and repaired with one. A spelling KiCad's parser refuses and `float()` reads (`+90`, `9_0`, `1e-400`) is read as the number `float()` gives, not refused: bug 70, step 12b. A rotation is written as KiCad writes it unless the angle atom already holds that text, so it repairs those spellings too. A call at the symbol's own position turns it in place, with no grid snap and no page check. The contact report only advises: what it cannot compute is reported as "Connections were not checked" and the move goes ahead.
- **No junction on a wire interior.** kicad-cli 9 cuts a wire at a junction inside it, so every junction a tool places is made from `_JUNCTION_TPL` inside `schematic._join_points`, which decides by `_connectivity.junction_info` (KiCad 9's AnalyzePoint) and splits each wire and bus through the junction as KiCad's `SCH_LINE::BreakAt` does. `test_every_junction_is_written_through_the_join_helper` scans the source for `_JUNCTION_TPL`, because a junction spliced directly passes every functional test. flatten_hierarchy and duplicate_sheet do not place junctions: they copy those a sheet already holds, with the wires around them. Files earlier versions wrote are found by `validate_hierarchy`, which names the add_junctions or remove_junction call that repairs each such junction.
- New constructs the server emits come from templates harvested from KiCad's own output (or verbatim copies of system-library nodes), not hand-written s-expressions.

### Path and tool resolution (`_shared.py`)

Config priority: explicit tool parameter > `KICAD_SCH_PATH`/`KICAD_PCB_PATH`/`KICAD_SYM_LIB`/`KICAD_FP_LIB`/`KICAD_OUTPUT_DIR` env vars > auto-detect from a single `*.kicad_pro` in cwd (resolved at import time into module constants). `kicad-cli` resolves via `KICAD_CLI_PATH`, then PATH, then the macOS app bundle, then the default Windows install roots (`_KICAD_WIN_DIRS`: Program Files and per-user LOCALAPPDATA, highest version number first); everything else in the install (stock symbol libs, the pcbnew Python used by `fill_zones`/`autoroute_pcb`) derives from the resolved binary's location (`_kicad_root`), unless `KICAD_SYMBOL_DIR` or `KICAD_PYTHON` overrides it. CLI-backed tools are always registered and fail with an actionable message when `kicad-cli` is missing. `_run_cli` also repairs one specific crash: exit `_KICAD_STARTUP_CRASH` (3221225477) means KiCad could not create its data folder, so it retries once with `KICAD_DOCUMENTS_HOME` set to a local path and caches that in `_documents_home`. Gate on the exit code, never the stderr text, which is locale-dependent. Any process that died rather than exited (`_died`: a negative return code, or an NTSTATUS at or above 0xC0000000) raises regardless of `check`, because `check=False` exists for ERC and DRC violation counts, not for a crash; `_run_pcbnew` applies the same rule to the pcbnew scripts. A footprint library nickname (`place_footprint`, `update_pcb_from_schematic`) resolves through one `pcb._FpLibResolver`, in KiCad's own order: the project's `fp-lib-table` (`_project_dir`: the `.kicad_pro`'s directory, else the first of the board's and schematic's directories holding a table or a project), then `.pretty` directories beside the board (and the schematic, for the import) and `KICAD_FP_LIB` (`_fp_search_dirs`), then the user's global `fp-lib-table` under KiCad's versioned settings directory (`_global_fp_lib_table`) merged with the libraries the Plugin and Content Manager installed (`_pcm_footprint_libs`: each `.pretty` inside a package under `${KICAD<N>_3RD_PARTY}/footprints`, as `<pcm.lib_prefix><lib>` while `pcm.lib_auto_add` is on, following KiCad in skipping a library the table already lists by URI and in numbering a taken nickname `_1`, `_2`), then the stock footprints under `_kicad_root`. The global table is read only after the local lookups miss, once per resolver. `_kicad_var` expands `${KIPRJMOD}`, then the OS environment, then Preferences > Configure Paths (`kicad_common.json` `environment.vars`), then KiCad's own defaults (`KICAD<N>_3RD_PARTY` under `_kicad_documents_home`, the `KICAD*_FOOTPRINT_DIR` family under the install); `_read_fp_lib_table` follows a `(type "Table")` row, and takes a row's URI as KiCad 9 reads it (`Atom.text`, escapes decoded) and, when that names nothing, as KiCad 10 reads it (the bytes between the quotes, `_uri_readings`), because the two majors read a hand-written `${KIPRJMOD}\footprints\X.pretty` as different paths.

### Tests

Fixtures in `conftest.py` build schematics/boards through kiutils builders. `kicad_native_sch` mirrors KiCad's own output format where kiutils' differs; prefer it when testing format fidelity. A write-path test states what the tool should change through `tests/edit_judge.py`, which reads both files with KiCad's own lexer rather than the CST: `assert_inserted` and `assert_removed` (whole items only, one span on token boundaries unless `contiguous=False`, the expected `heads`; a no-op fails), `atom_changes` (the exact list of changed atoms, failing if anything else changed, separators included), and `assert_confined` (every change inside the item at one path). Never a byte budget: a budget is fitted to today's output and pins whatever it does wrong.

The `conftest.py` helpers that read a verdict from `kicad-cli` (`run_erc`, `netlist_nodes`, `netlist_fields`, `assert_kicad_parseable`, `assert_kicad_pcb_parseable`, and the oracle's library checks) have it write its report into a directory made for that one run: `kicad-cli` writes nothing for a file it cannot load, so a report left beside the file by an earlier run would pass for its verdict. `assert_kicad_parseable` loads every sheet file below a schematic on its own, because `kicad-cli` loads a root whose sheets fail and says nothing; a missing sheet file, a sheet that names none, or a sheet that is its own ancestor fails outright, as KiCad's editor refuses all three. `_sheet_files` decides which file a sheet names by the installed `kicad-cli`'s major, because KiCad 9 and KiCad 10 read a hand-edited sheet's properties differently. `netlist_nodes` keys nets by printed name and refuses a netlist where two nets print alike, which kicadxml's unescaped names allow; where names can collide, compare by node set through `tests/netlist_oracle.py`, whose `is_named` counts a name as N only as N itself or after one of the design's sheet paths. `reparse` reads through kiutils, not KiCad: assert what KiCad reads through the CST, `tests/kicad_ref` or `kicad-cli`.

The test ladder: files named `tests/test_ladder_r<N>_<topic>.py` form rungs, each proving one layer and trusting only the rungs below it (1 bytes and tokens, `_cst.py` and the judges; 2 numbers and geometry; 3 single-element edits; 4 whole-file reads; 5 one tool call over the live registry; 6 composite tools; 7 end to end). Every test has a judge that is not the code under test: math (a round trip, an inverse, a composition), KiCad itself (kicad-cli, pcbnew, files KiCad saved, KiCad's source) or a domain rule. Never assert what the code does because it does it. A port of KiCad's source used as a judge lives in `tests/kicad_ref/`, cites file and lines at each tag it was read from (9.0.8, plus 10.0.7 where they differ), imports nothing from `mcp_server_kicad`, and is checked against KiCad itself in the judges file of the rung that adds it (`test_ladder_r<N>_judges.py`).

Shared geometry helpers: `tests/geom_judge.py` is exact plane geometry in integers and Fractions (orientation, segment distances, winding number, the nesting parity KiCad builds board outlines by, arc extremes) and imports nothing from the repository. `tests/geom_gen.py` holds the geometry strategies and writes boards, footprints, footprint libraries and the R1 schematic from templates embedded in it, every number spelled as KiCad spells it, never through kiutils or the code under test. `tests/kicad_corpus.py` finds the files the KiCad install ships; a corpus test takes files up to its `PER_PUSH_CAP` on every push and every file in its `test_nightly_` sibling. `tests/pcbnew_judge.py` runs a script under KiCad's own Python with pcbnew, and a failure of the run itself is a `RuntimeError`, never an `AssertionError`. A coordinate or angle a tool prints is judged by KiCad's reading of it: parse the text with `kicad_ref.parse_units` and compare the integer KiCad would hold, so any spelling KiCad reads the same way passes. `tests/test_ladder_r2_writers.py` calls each writer with off-grid and float-noise requests and judges every number it writes and reports that way. `tests/kicad_ref/lib_table.py` ports LIB_TABLE_ROW::Format, the table frame and the nickname rule, for the library table tests.

Footprint edit helpers: `tests/kicad_ref/footprint.py` (with `pad.py`, `pcb_text.py` and `board_layers.py`) reads a footprint as KiCad does and ports SetPosition, SetOrientation, Rotate and Flip over the board's own layer pairs, and `kicad_ref/exchange.py` ports the board update's footprint swap, the uuids it carries and the footprint lock. `tests/footprint_judge.py` compares footprints as KiCad reads them (texts as read, since neither parser runs KeepUpright on load; graphics by geometry; positions within 2 nm off the quarter turns), token for token, and by the uuids a swap carries; its upright form (`upright=True`), which holds a text and the one KeepUpright makes of it as one, serves only laws that hold up to KeepUpright, never a comparison with pcbnew or a port. `tests/pcbnew_fp_ops.py` runs KiCad's own placement, turn, flip and exchange in pcbnew, one subprocess per batch, and reads the result per footprint. `tests/edit_gen.py` writes footprints (in KiCad 9's form, or KiCad 7's with fp_text Reference and Value), boards (front or back, any lock spelling, the constructs the tools refuse) and netlists as KiCad writes them, each checked against pcbnew or kicad-cli in `test_ladder_r3_judges.py`.

Wire and junction helpers: `tests/sch_judge.py` reads wires, buses, junctions and KiCad 10 groups with KiCad's lexer. Its `junctions_on_interiors` is the structural judge of every junction a tool writes (KiCad's own files hold none, `test_kicad_never_writes_a_junction_on_a_wire_interior`), and `assert_split_edit` and `assert_merge_edit` judge a BreakAt split and a DeleteJunction merge byte for byte, by uuid. The kicad-cli netlist anchors for a junction on an unsplit wire run on kicad-cli 9 only: kicad-cli 10 joins a wire through a junction on load, so it cannot see the cut, and the structural judge carries the check on every major.

Field helpers: `tests/kicad_ref/sch_field.py` reads a placed symbol's fields as KiCad's parser does, child by child in file order (the frame each property is read in, its offset in the symbol's frame, GetPosition and GetDrawRotation), and `test_ladder_r3_judges.py` checks it against where kicad-cli plots them. `tests/svg_judge.py` reads those plotted anchors from the invisible `<text>` element of kicad-cli's SVG, never from the stroked glyph boxes, which KiCad draws upright and so do not turn with a symbol. `tests/edit_gen.py` also writes sheets of placed symbols in KiCad's child order and in three orders it loads but never writes.

The only xfail allowed is `@pytest.mark.xfail(strict=True, raises=AssertionError, reason="bug N: <one line>; fixed by step S")`, on any test that fails because of numbered bug N and for no other reason, its reason naming the step S that fixes the bug; strict mode fails the run on an unexpected pass, so that step must remove the marker. A generated strict xfail pins inputs that fail today with `@example` (explicit examples run under every profile) and draws nothing through `st.data()`. A premise the judge rests on, such as kicad-cli refusing a file, raises `RuntimeError` rather than asserting, so a broken premise can never pass for the bug. The autouse kicad-cli oracle skips a test whose call phase xfailed and still validates a pass or an XPASS.

Hypothesis is a dev-extra dependency. `HYPOTHESIS_PROFILE` picks one of the profiles `conftest.py` registers: `ci` (the default everywhere: derandomized, no database, 200 examples), `nightly` (randomized, 5000 examples) or `mutation` (derandomized, no shrinking). Size a test with `sexpr_gen.budget(divisor)`, never a literal `max_examples`. A `@given` test takes no function-scoped fixture such as `tmp_path`; it makes a `tempfile.TemporaryDirectory()` per example. `tests/sexpr_gen.py` holds the strategies: the KiCad-written dialect (`kicad_doc`, `doc_with_target`, the escape bodies) and one strategy per hostile class. A test that drives kicad-cli or pcbnew with generated inputs carries `@pytest.mark.nightly`, which skips it unless the profile is `nightly`, and has a hand-picked sibling that runs on every push. GitHub runs `nightly.yml` only from main, so run the nightly command above before merging a change to that set.

Coverage finds unreached code; it proves nothing: a test earns its place by failing when the code under it is broken, which each ladder test was shown to do with a deliberate break.

`tools/routing_harness/` is the measurement harness behind `docs/adr-routing-safety.md`, ported from the routing pressure test's scratch scripts and kept textually close to them, so ruff, pyright, pytest collection and the sdist all skip it (`pyproject.toml`). It is not part of the package or of this suite; its own `smoke.py` is its regression check, and its README says what it reproduces and how.

The tool count is hard-coded, and tests pin only two copies (`EXPECTED_TOOL_COUNT` in `conftest.py`, the literal in `test_unified_server.py`). Nothing local checks `server.py`'s instructions, README.md (twice), `mcpb/manifest.json`, `skills/using-kicad/SKILL.md`, or `macos-discovery.yml`, which runs only on `main` and `ci/**` pushes, so grep for the old number whenever a tool is added or removed.

### CI

- `ci.yml`: lint + pyright + pytest matrix (3.11-3.14), no KiCad installed. Triggers on `ci/**` pushes too, so preverify branches get the full matrix. Each leg's interpreter comes from setup-uv's `python-version`, which exports `UV_PYTHON` and so outranks `.python-version`; a step asserts the leg runs the version it is named for. Until 2026-10-01 the matrix used actions/setup-python, which uv ignores, so every leg ran the `.python-version` interpreter, 3.10 then. `ci.yml` and `kicad-suite.yml` always run, with no `paths-ignore`, and each ends in a result job (`CI result`, `KiCad suite result`) that passes when every other job in its workflow passed, or was skipped because its `changes` job found a docs-only pull request; that way a check a ruleset requires always reports. `changes` skips the work for a pull request touching only files on that workflow's skip list (`.github/tools/docs_only.py` reads it: exact paths and `dir/**` prefixes, nothing else). `kicad-suite.yml`'s list is longer and adds the Markdown docs; `ci.yml`'s cannot, because `ruff format --check .` reads the Python blocks in every `.md`. A result job must name every other job of its workflow in `needs:`, or its check passes without that job (`test_ci_result_jobs.py`). Pushes are never filtered, since `release.yml` needs green push runs on the commit it releases. A file goes on a workflow's list only if nothing that workflow runs can fail on it, or something `ci.yml` checks on every change to it (that is why `README.md`, which every `uv sync` reads as the package readme, may be on `kicad-suite.yml`'s list and is not on `ci.yml`'s).
- `kicad-suite.yml`: full suite on Linux, once with KiCad 9 and once with KiCad 10 (a matrix over the `ppa:kicad/kicad-<series>-releases` PPAs, each failing unless kicad-cli and pcbnew report its major). Runs on PRs and `ci/**` pushes, so for a pull request from a branch outside `ci/**` it is the only KiCad 10 signal before merge, and it runs `TestKicad10E2E` too.
- `macos-discovery.yml`: macOS with KiCad 10. What it adds over the Linux 10.0 leg is platform discovery (the Homebrew symlink and bundle-only resolution). Runs only on pushes to `main` and `ci/**`, **not on PR branches**: validate platform-affecting changes pre-merge by pushing a `ci/**` branch.
- `windows.yml`: Windows, same trigger as the macOS job and the same reason. It installs **KiCad 10** from KiCad's own download at a version pinned in the file, so it is one of three KiCad 10 gates (with macOS and the Linux 10.0 leg) and runs the full suite. It is also the only test of the `_KICAD_WIN_DIRS` probe against a real install, since `shutil.which("kicad-cli")` is `None` on the runner. Windows-specific faults have a history of reaching users first, so a green PR says nothing about this platform.
- `nightly.yml`: every `tests/test_ladder_*.py` file under the `nightly` profile, daily and on manual dispatch, on Linux with KiCad 9 and KiCad 10 installed exactly as `kicad-suite.yml` installs them (same fatal version check). It is the only place the `@pytest.mark.nightly` tests run in CI, and a schedule runs only from the default branch, so it says nothing about a branch until that branch merges.
- `release.yml`: manual dispatch, and the whole release, in three jobs so that no credential shares a machine with code it does not need to trust: `gate` (read-only), `build` (read-only token, no secrets: bumps, packs and builds, then hands `dist/`, `bundle/` and the bump as a patch to the next job through an artifact) and `publish` (the `pypi` environment, the app token and both OIDC logins, running none of this project's code or dependencies; it applies the patch only after checking it touches the four bump files and nothing else). It runs no tests of its own: the gate is the evidence. Before anything else it refuses a dispatch from any ref but main, and a commit unless the latest push or workflow_dispatch run of `ci.yml`, `kicad-suite.yml`, `macos-discovery.yml` and `windows.yml` concluded success (for a release bump commit, the newest run across it and the commits it bumped decides, provided each bump changed only version lines in the three manifests and only this project's own version line in uv.lock; a bump whose re-lock changed anything else needs runs of its own). Its two third-party tools are fetched at pinned versions: mcpb through `npm ci` on `.github/tools/mcpb/package-lock.json` in `build`, and mcp-publisher checked against a recorded sha256 in `publish`. Bumping either means updating that pin, not removing it. Bumps the version (pyproject, uv.lock, plugin.json, server.json), packs the MCPB bundle, tags a GitHub release with the wheel, sdist and `.mcpb` attached, publishes to PyPI, then publishes to the MCP Registry with `mcp-publisher login github-oidc` (never the interactive device flow: that JWT expires five minutes after issue). Its bump commit is pushed with a token from the release GitHub App (`RELEASE_APP_CLIENT_ID` variable and `RELEASE_APP_PRIVATE_KEY` secret on the `pypi` environment, so only `publish` can reach them), because `main`'s ruleset requires status checks and the default GITHUB_TOKEN cannot bypass a ruleset on a user-owned repository; that push triggers CI, so a bump commit has runs of its own (older bumps, pushed with GITHUB_TOKEN, have none). `main` carries two rulesets: one blocks deletion and force-push with no bypass at all, the other requires the `CodeRabbit` status (pinned to CodeRabbit's app) and the `CI result` and `KiCad suite result` checks (pinned to GitHub Actions), with the repository admin and the release app exempt. They are separate so that the second's exemptions never reach the first. Registry ownership is proved by the `mcp-name:` token in the README as published on PyPI, and registry metadata is immutable per version, so description fixes need a new release. The registry step runs last and retries, because the registry rejects a package version PyPI is not serving yet. The `0.0.0` versions in `mcpb/manifest.json` and `mcpb/pyproject.toml` are placeholders the release stamps and never commits; do not bump them by hand.

New files are stamped with the KiCad 9 formats the templates were harvested at (`KICAD_SCH_VERSION = 20250114` in conftest; `_EMPTY_SCH_TPL` in `project.py`, `_SYM_LIB_TPL` in `symbol.py`, `_EMPTY_PCB_TPL` in `pcb.py`, the last harvested from `pcbnew.NewBoard` itself and asserted byte-identical to that harvest). Editing an existing file through the CST never changes its version stamp, so a KiCad 10 file stays KiCad 10, and as of the netlist-import migration that holds for every board this package edits. The two library upgrades are the only exception left and they exist to change the format.

### This repo is also a Claude Code plugin

`.claude-plugin/`, `skills/` (six design skills), `agents/` (reviewer subagents), and `hooks/` ship to plugin users. `hooks/hooks.json` blocks Read/Write/Edit on KiCad file extensions at the harness level, so file manipulation must go through the MCP tools. Its SessionStart hook injects all of `skills/using-kicad/SKILL.md` into every plugin session, so every line of that file is context each plugin user pays for. Changes under `skills/` and `agents/` are user-facing product, not internal docs. `test_skill_tool_coverage.py` fails unless every tool is named in backticks in some `SKILL.md`; `test_skills.py` pins the skill, hook and agent structure and keeps `plugin.json`'s version equal to pyproject's.
